# QUAP 知衡量化 · 用户使用手册

面向**使用**这套系统的人：操作员、研究使用者、以及接手运维的人。安装与上线步骤见[部署说明](部署说明.md)，内部实现见[系统架构设计](系统架构设计.md)与[系统框架](系统框架.md)。

---

## 1. 这是什么，不是什么

**是**：一套沪深 A 股的**研究工作台**。它从四个公开行情源采集数据、落进 PostgreSQL、导出成不可变的 Qlib 代次，再由 Qlib 模型产出**建议的目标权重**，供人工复核。

**不是**：

| 不是 | 说明 |
| --- | --- |
| 不是交易系统 | 平台**不报单、不连接券商**。所有「接受」动作只生成一条模型组合修订记录。 |
| 不是投资建议 | 所有输出都是**研究证据**。Qlib Report 是描述性统计，不是推荐，也不是目标权重。 |
| 不保证数据完整 | 公开源缺什么就缺什么。缺上市日期、缺成交额时平台**留空并标注**，绝不用模拟数据填补。 |
| 没有降级兜底 | Qlib 是必需组件。前置条件不满足时平台**拒绝产出**，而不是退回一套替代算法。 |

界面顶部横幅会一直显示：`沪深 A 股研究工作台 / 授权数据 · 独立研究 · 不执行交易`。

## 2. 谁能用：访问令牌

系统是**单操作员**模型，只有一个凭据：

```
deploy/secrets/api_token
```

- 看板登录：打开 `http://127.0.0.1:8501`，把该文件的内容粘进「访问令牌」框。
- API 调用：`Authorization: Bearer <令牌>`。
- 令牌只用于当前浏览器会话；关页面不会中断后台采集。
- **采集侧没有任何供应商令牌** —— 公开源不需要，所以 `deploy/secrets/` 只有三份文件（数据库密码、数据库 URL、操作员令牌）。
- 令牌是唯一凭据：**泄露即等于全权**。轮换流程见[部署说明 · 凭证更正与轮换](部署说明.md#凭证更正与轮换)。
- 不要把令牌贴进对话、shell 参数、截图、版本库或浏览器 URL。

看板里所有时间都是**北京时间**，列表里带 `_at` 的列会自动换算。

## 3. 启动与登录（本地 Docker）

```bash
export PATH="/Applications/Docker.app/Contents/Resources/bin:$PATH"   # macOS
export QUANT_BACKUP_DIRECTORY=local-backups                            # 必填，否则 compose 直接报错

qc() { docker compose -f deploy/compose.yaml -f deploy/compose.local.yaml "$@"; }

qc config --quiet                 # 校验配置，不打印插值后的密钥
qc up -d --build api dashboard    # 先起 API + 看板（依赖链会先跑 migrate）
qc ps -a                          # migrate 退出码 0 是正常的
```

想一次起齐采集链路：

```bash
qc up -d --build migrate api dashboard scheduler operations history
```

**改代码必须重建镜像**：容器里跑的是打包进去的代码，没有源码 bind mount。改完源码要 `qc build <服务>` 再 `qc up -d`，否则容器里还是旧逻辑。

登录后如果顶部出现 `待验证接口：...` 或就绪页显示 `Blocked`，先看第 8 节排查，**不要**去找「原生回退开关」——没有这个东西。

## 4. 看板：七个工作空间

左侧「研究空间」单选切换。`Overview` 与组合观察区**每 10 秒自动刷新**；其余页面手动切页或点按钮刷新。

### 4.1 Overview · 总览

回答一个问题：**现在有没有可用的建议？**

- 两张就绪卡片：`Daily` / `Five-minute`，显示 `Ready` 或 `Blocked`，下方逐条列出**阻塞原因**（例如 `no approved, qualified, unexpired Qlib model`）。这些原因就是待办清单。
- 两个页签展示当前最新的日频 / 五分钟建议；没有就显示 `No valid Qlib proposal`。
- 顶部状态带（ribbon）：API 连接、数据源、行情覆盖是否完整、采集是否暂停、有效行情计数、必需接口是否已验证。
- 市场板块概览三张卡片：科创板 / 创业板 / 沪深主板，显示**有效样本等权当日涨跌幅**与覆盖进度条。**红涨绿跌**，不是交易所指数，覆盖不足时不要过度解读。
- 「Collection controls」：`Update source data`（refresh）、`Check provider capabilities`（doctor）、`暂停/恢复采集`。
- 四个页签：
  - **任务中心**：后台任务进度；展开可看任务明细、选中失败任务重试。
  - **数据质量与告警**：过期/缺失行情、缺失最新日线、复权因子修订数；受限接口；持久化告警。
  - **服务与接口**：服务心跳、数据源能力表，可展开看接口验证详情。注意：**接口可访问 ≠ 字段验证通过**。
  - **运行设置**：改行情轮询间隔（15–3600 秒），带修订检查。

> 暂停采集只停**计划中的行情轮询**，不是全局停机；它不会停止 Qlib 训练/推理/分钟任务。

### 4.2 My Model Portfolio · 我的模型组合

管理**目标配置**（不是券商持仓）。

- 选一个已有组合或 `Create baseline` 新建。
- 权重表格可增删行；`symbol` 必须是沪深代码，`weight` 是**目标占比**；现金单独填。**各项与现金之和必须恰好为 1，平台不做归一化**。
- 保存后生成一条**修订**，带生效时间。历史修订可在「Baseline revision history」查看。
- 「Request daily diagnosis」用当前基线发起一次日频运行。
- 两个页签展示日频建议 / 五分钟叠加建议，可直接**接受**：
  - 勾选要接受的变更（默认全选）；
  - 填组合名；
  - **必须勾选确认框**「我理解这只会生成模型组合修订、不发送任何订单」；
  - 接受后**未勾选的基线权重保持不变**，剩余部分留在现金。
  - 建议已过期或生效时间已过时，接受会被关闭，需要重新生成一份。
- 「Provenance」展开可看到 `源 → 数据集 → 模型 → 预测 → 评估 → 决策` 的完整链路。

### 4.3 Stock Research · 个股研究

两个页签。

**量化分析报告**：按交易日生成/刷新一份量化分析报告（点「生成/刷新报告」提交后台任务）。报告包含因子分组、综合榜等；顶部有免责声明。也可在服务器上用 `quant-platform report --as-of YYYY-MM-DD` 生成。

**Model views**：

- 搜索股票（代码或名称）。
- 选「组合上下文」：`Standalone model view` 或某个已保存组合。
- 输入股票代码 → 看**不复权人民币价格**走势与成交量图。注意：这是**展示数据**，不是 Qlib 建议，也不是预期收益。
- 日频 / 五分钟页签：模型视图 JSON + 历史 Qlib 评分/排名（带原始特征截断时间与观测时间，**不是可执行建议**）。
- 「Add to watchlist」把股票加入下一交易日的候选池；新加入的股票在历史就绪前会一直处于 `warming_up` 状态。
- 底部「Watchlist」可整批编辑观察列表（逗号分隔）。

### 4.4 Qlib Report · Qlib 研究报告

纯研究证据页，**不构成投资建议**：

- 因子 IC、Rank IC、日均 IC、有效样本数；
- 五分位分组表（分位 / 数量 / 平均未来收益）；
- 相对基准的等权组合：每 20 个交易日再平衡、取动量前 30 只等权，**已扣佣金、印花税与滑点**；显示调仓次数、平均单边换手，以及逐期明细（交易日、结束交易日、持仓数、组合净收益、基准收益、单边换手）。
- 报告由不可变代次导出后自动排队生成，写在 `reports.kind='qlib'`。

> **重要**：IC 为**负**表示按当前因子定义，动量与未来收益**反向**。照此选股会得到相反结果。这里只是描述现状，不代表任何操作建议。

### 4.5 Low-Price Scan · 低价股扫描

用 Qlib 预测给低价股排序，**不是按便宜程度排序**。

- 先设扫描策略：最高原始股价（元）、最低 20 日成交额（元）、最低上市交易日数（≥60）。保存会生成新的策略修订。
- 页面明确提示：低价不等于低风险或低估；分数是**模型排名**，不是概率。
- 风险警示股被排除。**策略变更会使既往报告失效**，需要一份匹配的、已通过资格的模型发布才能重新出建议。
- 下方列出当前日频建议中的低价候选。

### 4.6 Models & Validation · 模型与验证

三个页签。

**Releases & diagnostics**

- 选频率（`day` / `5min`）→ `Train challenger` 发起一次训练。
- 模型列表（id / 频率 / 状态 / 是否通过 / 创建时间 / 过期时间）。
- 选中模型看评估与产物；下方是**影子观测**记录。
- 展开「Realized quality, drift, and training importance」看实盘质量、漂移与训练重要性。
- 状态为 `shadow` 时可「Observe challenger on latest live cutoff」。
- 提升/回滚：**必须先勾选**「我已复核评估、血缘证据、策略与模型时效」。提升要求同一工作流血缘下 20 个健康生产交易日、该模型自身证据、以及时效。
- 提升成功后：**没有原生回退**。

**Factor library**：实验性因子定义，**不能作为目标权重被接受**。

**Experiments & configurations**：实验与训练配置管理。

### 4.7 Data & Pipeline · 数据与流水线

排障主入口，全部可展开。

- **Research sources, collection, and quality center**：研究源、采集与质量中心。
- 就绪卡片（与 Overview 相同）。
- **Pipeline runs**：每次流水线运行的 `id / 频率 / 用途 / as_of / 状态 / 错误`。选中可看步骤明细与固定输入快照。状态为 `blocked` / `failed` 时可「Retry same immutable inputs」——**改输入必须新建一次运行**。五分钟的推理/影子运行不可重试。
- **Immutable Qlib generations**：不可变代次表（`id / 频率 / origin / watermark / as_of / contract / path / created_at`）。`origin=scheduled` 是调度产出的日报代次，`origin=pipeline` 是流水线预备代次，两者用途不同。
- **Collection, permissions, jobs, and recovery**：完整运维面板（第 4.1 节的四个页签）。
- **Legacy native reports · read-only archive**：历史原生报告，只读归档，**已排除在当前建议与接受之外**，可导出 JSON。

## 5. 命令行工具

```bash
quant-platform <action> [选项]
```

| action | 用途 | 示例 |
| --- | --- | --- |
| `migrate` | 应用数据库迁移到 head | `quant-platform migrate` |
| `api` | 启动 API（默认 `127.0.0.1:8000`） | `quant-platform api --port 8000` |
| `dashboard` | 启动 Streamlit 看板（默认 `127.0.0.1:8501`） | `quant-platform dashboard` |
| `worker` | 启动工人，**必须带 `--role`** | `quant-platform worker --role history` |
| `status` | 打印完整运行状态 JSON | `quant-platform status` |
| `doctor` | 探测四个公开源可达性并写能力记录 | `quant-platform doctor` |
| `health` | 心跳检查，退出码 0/1（容器健康检查用） | `quant-platform health --role scheduler` |
| `report` | 生成量化分析报告并打印 Markdown | `quant-platform report --as-of 2026-09-24` |
| `import-legacy` | 导入旧监控运行时（默认干跑） | `quant-platform import-legacy --runtime /legacy-runtime` |
| `restore-check` | 从备份包恢复到空库并核对 | `quant-platform restore-check --archive … --target-dsn-file …` |

`--role` 可选值：`scheduler`、`quotes`、`history`、`analysis`、`operations`、`notify`、`minute-history`、`minute-live`、`qlib-data`、`qlib-train`、`qlib-daily`、`qlib-intraday`、`research-data`、`qlib-research`、`qlib-diagnostics`。

`import-legacy` 加 `--apply` 才真正写入；不加是干跑。`restore-check` 还接受 `--fault-at <ISO 时间>` 记录 RPO/RTO，以及 `--artifact-destination <新目录>`。

容器里执行：

```bash
qc exec -T api quant-platform status
qc exec -T api quant-platform doctor
```

## 6. HTTP API

- 基地址：`http://127.0.0.1:8000/api/v1`
- **全部接口都需要** `Authorization: Bearer <令牌>`（唯一例外是 `GET /health/live`）。
- **没有 `/docs` 与 `/openapi.json`**（有意关闭）。接口清单以本文档与看板为准。
- 错误语义：

| 状态码 | 含义 | 用户该做什么 |
| --- | --- | --- |
| `401` | 令牌无效或缺失 | 重新登录 / 检查令牌文件 |
| `409` | 冲突或前置未就绪（含流水线阻塞） | 刷新页面，检查版本、交易日与任务状态 |
| `410` | 该功能已退役（`PUT /rules`、旧篮子写操作） | 改用版本化的模型组合 / 扫描策略 |
| `422` | 入参不合法 | 检查代码格式、权重、字段范围 |
| `503` | 后端异常或认证未配置 | 看容器日志与 `status` |

### 调用示例

```bash
TOKEN=$(cat deploy/secrets/api_token)
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8000/api/v1/data-readiness
```

```python
import json, urllib.request
token = open("deploy/secrets/api_token").read().strip()

def get(path):
    req = urllib.request.Request("http://127.0.0.1:8000/api/v1" + path,
                                 headers={"Authorization": f"Bearer {token}"})
    with urllib.request.urlopen(req, timeout=30) as r:
        return json.loads(r.read().decode())

print(get("/data-readiness")["frequencies"]["day"]["blockers"])
```

写入类接口（`PUT /settings`、`PUT /watchlist`、`PUT /model-portfolios/{id}`、`PUT /scan-policy`）都要求 `expected_revision`。这是**乐观锁**：拿到旧修订号再写会得到 `409`，请重新读取当前修订。

## 7. 配置项

通过环境变量提供。**在宿主机 shell 里 export 不会注入容器** —— 要写进 Compose override 并作用到所有相关服务。

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| `QUANT_DATABASE_URL` / `_FILE` | — | 数据库连接（容器里用文件） |
| `QUANT_API_TOKEN` / `_FILE` | — | 操作员令牌 |
| `QUANT_REALTIME_RPM` | 40 | 实时请求每分钟上限 |
| `QUANT_ORDINARY_RPM` | 20 | 普通请求每分钟上限（决定历史回填**轮次**） |
| `QUANT_DAILY_QUOTA` | 8000 | 每接口每日请求上限 |
| `QUANT_MINUTE_RPM` | 40 | 分钟线每分钟上限 |
| `QUANT_MINUTE_DAILY_QUOTA` | 8000 | 分钟线每日上限 |
| `QUANT_QUOTE_SECONDS` | 30 | 行情轮询间隔基准（看板可改，带修订检查） |
| `QUANT_HISTORY_SESSIONS` | 1500 | 分析窗口会话数 |
| `QUANT_FACTOR_SESSIONS` | 500 | 可接受的最小**连续已复权**会话数 |
| `QUANT_MINUTE_HISTORY_SESSIONS` | 252 | 分钟线历史会话数 |
| `QUANT_INTRADAY_POOL_CAPACITY` | 300 | 盘中池容量上限 |
| `QUANT_HISTORY_SCOPE` | `index` | `index` 只采沪深 300 成分 + 观察篮子；`all` 才采全市场 |
| `QUANT_ENVIRONMENT` | `production` | 生产证据要求 `production`；改标签不能把夹具变成证据 |
| `QUANT_BACKUP_DIRECTORY` | — | 备份目录（Compose 必填插值） |
| `QUANT_BACKUP_REPLICA_ROOT` | — | 异地副本目录；不设则只保留主备份 |
| `QUANT_OBSERVATION_ROOT` | `/data/observations` | API 事件 JSONL 落盘位置 |
| `QUANT_NOTIFY_WEBHOOK` | 空 | 操作员 Webhook；**留空则告警不外送**，只在库里 |
| `QUANT_TRAINING_DEADLINE_SECONDS` | 21600 | 训练超时 |
| `QUANT_DATA_DEADLINE_SECONDS` | 7200 | 数据步骤超时 |
| `QUANT_API_URL` | `http://127.0.0.1:8000` | 看板连接的 API 地址 |

**配额决定收敛速度，不只是速度**：一轮能覆盖的证券数 = 该分钟窗口允许的请求数（默认 20）。用尽后把余量交给只等一个窗口的续跑任务，**有进展的轮次不消耗重试预算**。

## 8. 日常运维节奏

系统按北京时间自动推进：

| 时间（北京） | 发生什么 |
| --- | --- |
| 08:30 起 | 入队 `calendar`、`securities` 任务，刷新交易日历与证券主表 |
| 09:20 起（交易日） | 入队当日 `factors`（只写复权因子）与当日 `constraints` |
| 09:30–15:00（交易日） | 行情轮询（间隔 = 30 秒 + 采集耗时）；分钟线实时采集 |
| 15:00 后 | 当日日线才**收盘定稿**，可以入库 |
| 18:30 起 | 分析截止日推进到今天；入队 `benchmark`、`history`、`constraints` 整窗采集 |
| 每日 | `maintenance` 创建/回收 `quotes`/`alerts`/`minute_bars` 的 T+1..T+3 分区 |
| 每日（分析截止日） | **按决策日**重新观测采集范围内的证券风险状态（ST/退市）。这是纯本地推导（读主表名称），不消耗任何源配额 |
| 每月 1 日 | 全表风险状态重扫一轮，覆盖采集范围之外的历史证券 |

**为什么风险状态要按决策日观测**：公开源不发布带日期的更名史，状态只能从它被观测的那一天起算，而代次只接受「覆盖决策日」的状态。月度全表扫描会把最新状态钉在当月 1 日，而 1 日 18:30 之前的决策日还是上月最后一个交易日 —— 那个窗口里没有任何状态覆盖它，覆盖率会**每月归零一次**。观测日因此是契约的一部分：`security_states.data` 里的 `observed_lag_days` / `backfilled` 会告诉你这一次观测是当日的还是回填的。

**日线只在收盘后发布**：盘中写入的 K 线是半成品，而 `daily_bars` 是 `ON CONFLICT DO NOTHING` 的，写进去就改不回来。所以早晨的刷新任务是 `factors` 类别，只写因子。

### 每周 / 每月建议动作

- 每周：看 `Data & Pipeline` 的失败/阻塞任务，确认 `maintenance` 正常；确认 `alerts` 没有堆积。
- 每月：确认 1 日的 `security_history` 周期跑完；跑一次异地副本恢复演练。
- 每次改动：改完源码必须重建镜像；改 `pyproject.toml` 必须先 `uv lock` 再 `uv sync --frozen`。

## 9. 故障排查速查

| 现象 | 先看哪里 | 常见原因 |
| --- | --- | --- |
| 就绪页一直 `Blocked` | 卡片下方的阻塞原因 | 缺模型 / 缺能力验证 / 缺数据，逐条对照 |
| `待验证接口：X` | `Data & Pipeline → 服务与接口` | 该能力还没有一次**成功的真实采集**；`doctor` 的可达性探测**不写**这个标记 |
| 登录失败：`访问令牌不正确` | `deploy/secrets/api_token` | 令牌不是**启动这个栈的那个目录**下的那一份。`deploy/secrets/` 不进版本库，所以同一台机器上的多个 checkout / git worktree **各有一份互不相同的令牌**，读错目录就会 401。用绝对路径复制：`tr -d '\n' < <仓库绝对路径>/deploy/secrets/api_token \| pbcopy` |
| 登录失败：`无法连接后端服务` | `qc ps`、`qc logs api` | API 容器未起或不可达；令牌本身没有问题 |
| 登录失败：粘贴后即报错、API 日志无记录 | 令牌是否含首尾空白 | httpx 会在发送前拒绝带空白的头值；`cat` 的输出带换行，看板会自行裁剪，但别手工删字符 |
| 「后端连接已断开」 | `qc ps`、`qc logs api` | API 容器挂了或网络中断；**已展示的数据不代表实时行情** |
| 行情覆盖不足 | 顶部 ribbon、数据质量页签 | 非交易时段也会出现；或源不可达 |
| 公开数据源不可达 | 点「接口诊断」，看 `status` 的 `missing` | 先查宿主机出网与 DNS；不要改绑定地址或加代理绕过 HTTPS 校验 |
| 任务反复失败 | 任务中心 → 展开 → 选中失败任务重试 | 看 `error` 字段；配额类失败等一个窗口即可 |
| 流水线 `blocked` | 选中运行看步骤明细与 `error` | 输入数据未就绪；改输入要**新建**运行 |
| 迁移报 `password authentication failed` | 密钥文件与 `postgres` 卷 | 密码文件与卷初始化时不一致，两者必须一起改 |
| `migrate` 容器退出码非 0 | `qc logs migrate` | 迁移失败；**旧镜像不能假定能读新迁移后的模式** |

排障两条硬规则：

1. **降级只由 `ProviderError` / `Deferred` 触发。** 源客户端的私有异常必须先在适配层转成 `ProviderError`，否则它会穿过降级链，把整个能力记成失败而不再试下一个源。
2. **一个源在某个字段上失败只影响该字段。** 主表缺上市日期照常发布（值留空并标注），因子拿不到成对价格就记「部分缺失」，**绝不把缺失 K 线解释成停牌**。

## 10. 使用前必须知道的三条边界

1. **平台不产出建议，除非模型已批准。** 当前默认部署下 `day` 就绪仍会被「无已批准模型」挡住 —— 这是**设计行为**，不是故障，也不是去打开某个开关。
   - 就绪页还会单列一条 `history scope is 'index'; production acceptance requires QUANT_HISTORY_SCOPE=all ...`：默认只采沪深 300 成分与观察篮子，**生产验收要求全市场覆盖**。采集范围是配置，不是数据缺陷，所以它独立成一条。
   - 训练宇宙等于采集范围，所以改 `QUANT_HISTORY_SCOPE` 会同时改变「采什么」和「训什么」；范围解析不出来（成分股取不到、观察篮子为空）时**流水线会明确拒绝建运行**，而不是悄悄退回全市场。
2. **`origin=scheduled` 的代次是日报数据，不是实验输入。** 实验只能选 `origin=pipeline` 的预备代次（看板已做过滤）。
3. **所有输出都要人工复核。** 提升模型、接受变更、发布报告，每一步都需要人勾选确认；系统不会替你决定。
