# 部署说明

本文在 QUAP 仓库根目录部署平台。架构边界见[系统框架](系统框架.md)，完整设计见[系统架构设计](系统架构设计.md)，仓库内功能验证见[系统验证报告](系统验证报告.md)。命令默认在仓库根目录执行；旧监控由操作员在其外部环境中独立运行。

The working-tree redesign is not yet production-qualified. These are separate states:

- **Services running:** PostgreSQL, API/UI, collection, and required Qlib workers are healthy.
- **Data available:** authorized endpoints return valid, dated data with adequate historical coverage; HTTP 200 is insufficient.
- **Monitoring live:** fresh source timestamps and explicit ownership have been verified during exchange sessions.
- **Recommendations available:** that frequency has a passing, manually approved, unexpired Qlib release and a current successful prediction with complete provenance.
- **Production accepted:** actual entitlements, point-in-time history, model performance, 20 healthy production shadow sessions, five-minute capacity/latency, consistent backup, and off-host recovery are verified.

The old two-session quote-monitoring metric is not a Qlib release gate. Fixture results do not demonstrate investment performance. These instructions do not imply that an existing running stack has already been migrated.

权限被拒绝时，平台仍可能显示为运行中，这不能称为实盘。缺少凭证时保持停止，不改用公开或合成行情。外部旧监控进程保留到明确批准的切换完成。

## 前提

- Docker Engine 与 Compose v2，或本机 Docker Desktop。
- 构建期间可以访问镜像和包仓库，并且可以经校验证书访问 Tushare。宿主机时钟与 Asia/Shanghai 对齐。
- Daily Qlib requires `stock_basic`, `trade_cal`, `daily`, `adj_factor`, `index_daily`, `namechange`, `stk_limit`, and `suspend_d`. Five-minute workflows also require `stk_mins`, `rt_min`, and `rt_min_daily`. Quote monitoring separately requires `rt_k`. Check actual account entitlements and endpoint-specific quotas; do not purchase or substitute permissions implicitly.
- 本地准备脚本使用 Python 3.11，没有第三方依赖。应用 Python 由镜像提供。
- Reserve capacity for PostgreSQL, collection, immutable artifacts, and four required Qlib workers. Compose limits training to 8 GiB and other engine workers to 4 GiB each, with four CPUs per engine container. These are limits, not a validated total-host budget. Measure memory, disk growth, and minute latency under concurrent training before activation.
- Engine images use Linux AMD64 with pinned Qlib/LightGBM. ARM emulation is a development option, not proof of production five-minute capacity.
- 连续监控需要宿主机保持唤醒。关闭浏览器是安全的；让 Mac 睡眠、退出 Docker Desktop 或关闭主机会停止采集。

## 本地 Docker

本地栈使用命名的 PostgreSQL、产物和备份卷。只绑定 `127.0.0.1:8000` 和 `127.0.0.1:8501`。PostgreSQL 没有宿主机端口。

把 Tushare 令牌私下写入：

```text
deploy/secrets/tushare_token
```

文件内容只能是裸令牌本身：不带 `token:` 之类的前缀、标签、引号或注释，末尾换行可有可无。`doctor` 返回 Tushare 应用码 `40101`（"您的token不对"）而不是权限拒绝时，先检查这个文件的格式。使用密钥管理器或私人编辑器。不要把令牌贴进对话、shell 参数、截图、版本库或浏览器 URL。`deploy/secrets/` 已排除在 Git、根目录 `.dockerignore`（因此也排除在镜像构建上下文之外）和发行包之外。`.dockerignore` 同时排除 `.venv`、`.runtime`、`legacy` 和 `tests`。

生成其余本地密钥：

```bash
python3 deploy/prepare_local.py
```

脚本只补齐缺失的 `postgres_password`、与之匹配的 `database_url` 和 `api_token`。它不替换、不打印已有凭证，拒绝不一致的本地数据库凭证和符号链接，并要求操作员已经放入非空 Tushare 令牌。重复执行不会轮换密码，也不证明供应商权限。

单操作员本机上，目录模式是 `0700`，每个文件是 `0444`。其他本机用户不能进入目录，容器 UID 10001 仍能读取单独挂载的文件。多用户 Linux 服务器改用密钥管理器和按 UID 管理的挂载，不要沿用这套本机权限。

定义当前 shell 的助手函数：

```bash
export QUANT_BACKUP_DIRECTORY=local-backups
qc() {
  docker compose \
    -f deploy/compose.yaml \
    -f deploy/compose.local.yaml "$@"
}
qc config --quiet
qc up -d --build api dashboard
qc ps -a
```

依赖链会先启动 PostgreSQL 并完成迁移，再启动 API 和看板。`migrate` 以退出码 0 结束是正常的。这一步不启动工人。校验配置使用 `config --quiet`，避免把插值后的密钥打出来。

Open `http://127.0.0.1:8501` and enter the operator token from `api_token`, never the Tushare token. Read secrets privately. The six workspaces are Overview, My Model Portfolio, Stock Research, Low-Price Scan, Models & Validation, and Data & Pipeline. Until models/data qualify, blocked recommendations are expected—not a request to enable native fallback.

## 暂停、探测，然后引导

Before transferring ownership from an existing collector, pause legacy quote polling using the authenticated control API below. This control pauses scheduled quote cycles only: it is not a global Qlib training/inference/minute stop. Do not start minute workers or enable publishing until the relevant cutover prerequisites pass. For maintenance of an already active deployment, stop the scheduler and drain affected collection/inference workers as well.

```bash
qc exec -T api python - <<'PY'
import httpx
from quant_platform.config import Settings
settings = Settings()
response = httpx.post(
    "http://127.0.0.1:8000/api/v1/control",
    headers={"Authorization": "Bearer " + settings.api_token.get_secret_value()},
    json={"action": "pause"},
    timeout=10,
)
response.raise_for_status()
print({"quote_polling_paused": response.json()["applied"]})
PY
```

然后探测实际权限：

```bash
qc exec -T api quant-platform doctor
qc exec -T api quant-platform status
```

看返回的 `missing` 列表和能力记录，不要只看进程退出码。`blocked` 且 `configured=true, entitled=false` 表示凭证或必需权限被拒绝。传输成功不能覆盖应用层拒绝。任一必需接口缺失就停止开通，先修正凭证或权限，不要对已拒绝的账户反复探测。

With quote polling paused, begin historical preparation on the intended deployment only after permissions and upgrade/backup checks:

```bash
qc up -d --build scheduler history minute-history operations qlib-data qlib-train qlib-daily
qc exec -T api quant-platform status
qc logs --tail=100 history minute-history qlib-data qlib-train
```

This is a staged startup, not the completed standard deployment. The scheduler can enqueue live-minute work even while quote polling is paused; do not start its consumers until ownership is approved. Missing permissions remain blocked and no public-data fallback exists.

Check Data & Pipeline and authenticated `/api/v1/data-readiness`:

- Verified exchange calendars, listed/delisted identities, historical security states, dated limits, and benchmark history.
- Default 1,500 completed daily sessions, with raw OHLC, physical volume, turnover, and source factors. Short fixtures cannot qualify production models.
- Frozen normalization anchors and correct raw/Qlib unit round trips; gaps and omissions remain explicit.
- Passing daily held-out evaluation and reconstructed dated out-of-sample minute pools. `research_minutes` shows required/completed scoped source jobs.
- Default 252 historical pool sessions and 20-session live warm-up. Finished jobs alone do not prove all 48 active-day bars have valid feature history.
- Immutable generation/model/recorder manifests and a successful database/artifact backup followed by restore validation.

Models & Validation separates training, evaluation, shadow evidence, and promotion. Daily and minute models train independently. Each candidate needs its own passing evaluation and healthy completed production session, plus 20 healthy sessions of matching workflow lineage in the preceding 60-day window and manual approval. Candidate-owned evidence uses the same window. The current Shanghai date and future dates do not count, and both exchange calendars must confirm an open session. Intraday sessions require all 44 eligible cutoffs; missing cutoffs remain visible in shadow observations. Daily models expire after 35 calendar days; minute models after 14. Missing gates must not be weakened automatically.

引导时长取决于账户限额和实际数据缺口。日志里没有报错，或容器健康，都不能当作完成。

## 配额

应用默认是每分钟 40 次实时请求、每分钟 20 次普通请求，以及每个接口每天 8000 次。周期间隔默认是 30 秒加上采集耗时。配置不要高于账户实际额度。持久的行情间隔可以在看板里修改，并带修订检查。

Configuration includes `QUANT_REALTIME_RPM`, `QUANT_ORDINARY_RPM`, `QUANT_DAILY_QUOTA`, `QUANT_MINUTE_RPM` (40), `QUANT_MINUTE_DAILY_QUOTA` (8000), `QUANT_HISTORY_SESSIONS` (1500), `QUANT_MINUTE_HISTORY_SESSIONS` (252), and `QUANT_INTRADAY_POOL_CAPACITY` (300). Pass nonforwarded settings through a Compose override to all relevant services; exporting them in the host shell alone does not inject them. Keep provider quotas consistent across API probes, history, quotes, minute workers, and operations, and history/pool policy consistent across scheduler and engines.

The base Compose explicitly forwards `QUANT_TRAINING_DEADLINE_SECONDS` (21600) and `QUANT_DATA_DEADLINE_SECONDS` (7200). Inference/shadow defaults to 120 seconds and remains constrained by the bar publication deadline. Production evidence requires `QUANT_ENVIRONMENT=production`; changing the environment label cannot turn synthetic fixtures into legitimate evidence.

`QUANT_OBSERVATION_ROOT` 在容器里是 `/data/observations`，API 事件写在进程外。`QUANT_BACKUP_REPLICA_ROOT` 指向与主备份不同的目录时，备份作业会再复制一份并核对校验和；不设置就只保留主备份。`QUANT_NOTIFY_WEBHOOK` 只给 `notify` 服务，是操作员自己的 Webhook；留空则不外送，告警仍留在库里。

## 旧监控迁移与所有权切换

新界面启动后，不要因此停掉仍健康的旧采集器。保留它的配置和运行时文件。新的证券主数据和日历可用之后，把外部旧监控的运行时目录（含来源 SQLite）用只读挂载导入。将 `LEGACY_RUNTIME` 指向操作员自有的旧监控运行时路径：

```bash
export LEGACY_RUNTIME="/absolute/path/to/legacy-monitor/.runtime"
qc run --rm --no-deps \
  -v "$LEGACY_RUNTIME:/legacy-runtime:ro" api \
  import-legacy --runtime /legacy-runtime
```

检查篮子数量、实盘事件数量和未能解析的宇宙。确认来源 SQLite 可读，包括 WAL 状态。后续导入使用同一容器挂载路径，因为它属于来源身份。干运行和迁移范围批准后：

```bash
qc run --rm --no-deps \
  -v "$LEGACY_RUNTIME:/legacy-runtime:ro" api \
  import-legacy --runtime /legacy-runtime --apply
```

导入保留篮子身份，复制实盘告警，排除演示告警，并且不把旧的复权价格当作原始 Tushare 价格。来源变化会生成修订；本地篮子编辑或控制产生冲突，而不会被覆盖。命名宇宙需要经过验证的带日期成分适配器。

Verify imported membership, weights, alert policy, and effective dates. Migration `0004` copies baskets already present at upgrade into model-portfolio baselines with explicit zero cash. Imports performed afterward remain legacy monitoring records; create and verify the intended target-weight baseline through the model-portfolio API/UI rather than assuming a second automatic migration. Neither imported nor manually entered baselines are actual brokerage holdings.

Before an approved ownership switch, stop/drain the old collector using its own operating procedure and confirm it no longer owns collection/alerts for the scope. Then resume quote polling through the control API and start the remaining standard services:

```bash
qc up -d --build quotes analysis minute-live qlib-intraday notify
qc ps -a
```

Check fresh source timestamps and separately valid daily/minute recommendations during verified sessions. Daily availability is not completion of the minute scope. Missing minute data/release/deadline leaves intraday unavailable and the daily baseline separately labeled. Nighttime silence is not evidence of failure.

开通失败时，先暂停并排空替代采集器，再按批准的步骤回滚到旧监控。旧监控的重新启动按其自身运维流程执行。两套实盘所有者不能同时运行。外部研究数据集保持原样。

## 凭证更正与轮换

Tushare 令牌被拒绝时，先向供应商核对账户和接口权限。轮换前暂停轮询，并在替换挂载文件时停止新的工人。这一步不要停止仍保留的旧进程。

```bash
qc stop scheduler quotes history analysis minute-history minute-live qlib-data qlib-train qlib-daily qlib-intraday operations notify
chmod 600 deploy/secrets/tushare_token
```

私下编辑该文件，再运行准备脚本校验本地配置并恢复受保护目录的挂载权限。重建 API 容器，避免宿主机文件被原子替换后仍留下旧的绑定挂载：

```bash
python3 deploy/prepare_local.py
qc up -d --force-recreate api
qc exec -T api quant-platform doctor
```

必需能力通过之后，再重建工人：

```bash
qc up -d --force-recreate scheduler quotes history analysis minute-history minute-live qlib-data qlib-train qlib-daily qlib-intraday operations notify
```

实盘所有权切换条件通过之前，轮询保持暂停。doctor 只解除依赖已经重新验证的任务，不会自动恢复轮询。不要只轮换 PostgreSQL 密码文件而留下旧数据卷：数据库角色密码和 `database_url` 必须通过明确的数据库凭证轮换一起修改。本地准备脚本不做这件事。操作员令牌单独轮换，并按需要重建 API 会话。

## Linux 生产

使用同一份基础 Compose 文件，**不要**叠加 `compose.local.yaml`。四个私有文件由密钥管理器提供，容器 UID 10001 可读。PostgreSQL URL 必须匹配数据库密码。另备一份 UID 10001 可写的持久备份目录，并在 Docker 宿主机之外安排机外复制和恢复入口。

```bash
export QUANT_BACKUP_DIRECTORY=/srv/quant-backups
qc() {
  docker compose -f deploy/compose.yaml "$@"
}
qc config --quiet
qc up -d --build api dashboard
```

随后沿用上面的暂停、doctor、引导、迁移和切换步骤。这套单机栈不是高可用部署。还需要配置 Docker 的宿主机启动策略、磁盘监控、备份复制和运行告警。

端口保持只绑定回环地址。操作员工作站通过隧道访问：

```bash
ssh -N -L 8501:127.0.0.1:8501 -L 8000:127.0.0.1:8000 operator@server
```

然后使用本机看板地址和操作员令牌登录。对公网开放需要单独配置 TLS 和认证边界，不要把绑定地址直接改成互联网接口。

## Required Qlib runtime and upgrades

There is no optional Qlib Compose profile. Standard services are `qlib-data`, `qlib-train`, `qlib-daily`, and `qlib-intraday`; the old `research` and `qlib` services are retired. `QUANT_QLIB_ENABLED=false` is rejected. Packaging still uses an engine extra so the lightweight API/ingestion image does not install Qlib, MLflow, or LightGBM.

Before upgrading an existing native deployment: preserve a verified pre-upgrade backup, stop/drain scheduling and writes, build compatible images, migrate through `0008`, verify legacy baseline conversion and additive research-role grants, and perform staged startup. Do not assume an older image can read the new schema. Existing native reports stay read-only `legacy_native`; candidate approval cannot create new recommendations.

Operational rollback chooses a still-qualified approved Qlib release through the explicit rollback API, or enters monitoring-only mode. It must not reactivate native rankings. A schema rollback requires restoring a verified backup under an explicit operating procedure. The plan's implementation does not itself authorize production migration or restarting an existing stack.

## Optional research workers

The new `research` profile is separate from the retired generic research service and from the four mandatory Qlib roles. Do not enable it on an existing deployment until schema/image compatibility and backup checks pass. These commands are operator procedures, not authorization for an automatic stack restart.

```bash
qc --profile research config --quiet
qc --profile research up -d --build qlib-research qlib-diagnostics
```

Experiments and diagnostics can run without adata or any provider token in those containers. Each queue defaults to concurrency one. `qlib-research` has 2 CPUs / 8 GiB / 256 PIDs and the existing training deadline; diagnostics has 2 CPUs / 4 GiB / 256 PIDs. Pending diagnostic intent can remain queued while its optional consumer is stopped; reads never start it. Validate host contention against live inference before enabling research workloads.

Supplemental network collection needs a separate explicit deployment opt-in:

```bash
export QUANT_RESEARCH_DATA_ENABLED=true
qc --profile research config --quiet
qc --profile research up -d --build api research-data
```

Then in Data & Pipeline, review upstream data terms, explicitly enable the desired source revision, and request named stocks/dates. Deployment enablement alone does not schedule a scrape. The research-data image installs `adata==2.9.5`, has 1 CPU / 2 GiB / 128 PIDs, and mounts only the DB secret. The trusted parent performs DB access/publication; subprocess environments contain no DB, provider, or operator credentials. API/dashboard/required Qlib images do not install adata.

The source-specific adapter allows only selected Eastmoney HTTPS endpoints, raw prices, certificate verification, no redirects/environment proxies, and bounded transport. Defaults/maxima are ten requests/minute, three attempts, 60 seconds/request, 8 MiB/response, and 50 stocks/job. Reduced `QUANT_RESEARCH_RPM`, `QUANT_RESEARCH_ATTEMPTS`, `QUANT_RESEARCH_REQUEST_DEADLINE_SECONDS`, and `QUANT_RESEARCH_RESPONSE_BYTES` require an explicit Compose environment override on research-data; shell exports alone do not forward these settings.

Important limitation: adata 2.9.5's daily method requests HTTP and is rejected as unavailable. Do not weaken HTTPS policy or substitute another provider. Intraday is same-session only; fixture success is not live-provider certification. Retrieval time never establishes historical availability. Supplemental snapshots and quality differences cannot satisfy production readiness, watermarks, pools, model training, or shadow gates. Tushare remains the sole canonical source.

Source disablement appends a revision; in-flight publication rechecks it. Explicit research job cancellation increments the fence and marks the job blocked, preserving prior evidence. Retry requires the current control revision and a permanently bound idempotency key. Neither operation changes releases or model portfolios. For maintenance, drain/stop optional workers as well as affected standard roles; `qc stop` covers running services.

The optional dependency is [adata](https://github.com/1nchaos/adata), Apache-2.0. Its installed wheel retains `adata-2.9.5.dist-info/LICENSE`; keep upstream license/attribution metadata in redistributed images. QUAP does not vendor or modify that package's files. Upstream market-data terms are a separate prerequisite. No QuantMind AGPL integration code is copied, and RD-Agent/TradingAgents/paid-LLM installation or data egress is deferred to a separately approved stage.

## 运行、备份与关闭

```bash
qc ps -a
qc exec -T api quant-platform status
qc logs --tail=100 scheduler history minute-history minute-live qlib-data qlib-train qlib-daily qlib-intraday operations notify
qc restart history
```

容器重启保留数据库任务和检查点；过期租约和围栏保护发布。宣布恢复之前，检查源数据新鲜度、失败或阻塞任务、报告日期，以及观察是否可安全去重，而不是只看容器状态。API 延迟和错误指标覆盖该 API 进程五分钟内最近 1000 次请求，重启后清零。

Operations writes `quap-snapshot-v1` tar bundles containing `database.dump`, all referenced Qlib generations/models/recorders and research snapshots/trials/diagnostics, and a checksum manifest under one exported PostgreSQL snapshot. Seven committed owned bundles are retained. Database/artifact references and retained-backup references protect artifacts from pruning; this is not keep-two-generation retention. Abandoned generation/model/research directories and recorders carrying the exact `quap-owner.json` ownership marker can be pruned after the task grace period when no Qlib work is running, with at most 100 directories removed per pass. Referenced and backup-retained recorders are protected. Legacy/unmarked recorders, experiment metadata, malformed markers, and symlinks are left untouched; monitor their disk growth.

Local bundles live in `quant-platform_local-backups`; production uses the configured backup directory. A separate directory or Docker volume is not automatically another failure domain. Keep an encrypted off-host replica and test restoration from it. Do not delete volumes during troubleshooting. Backups are trusted operator inputs; checksums are not authentication against malicious replacement.

恢复演练使用单独的空库 `quant_restore_*` 及其私有 DSN 文件。把 DSN 文件挂进一次性运营容器，归档名使用备份状态里的实际文件名：

```bash
qc run --rm --no-deps \
  -v /absolute/private/restore_database_url:/run/secrets/restore_database_url:ro \
  operations restore-check \
  --archive /backups/quant-TIMESTAMP-ID.tar \
  --target-dsn-file /run/secrets/restore_database_url \
  --artifact-destination /backups/restore-artifacts-UNIQUE
```

Replace every placeholder with actual paths. The target must be an empty, separate `quant_restore_*` database; the artifact destination must not already exist and must be writable by UID 10001. Never restore over `/data/artifacts` or the production database. Malformed paths, links, duplicates, unsupported content, and checksum mismatches reject the bundle. The restored database's exact artifact references must match the bundle before the new artifact root is published. A failed database restore can leave the disposable target nonempty; repeat with another empty isolated target.

Optionally supply `--fault-at` with a timezone-aware ISO timestamp to record observed RPO/RTO differences. A successful local fixture restore does not prove off-host recovery or an RTO/RPO objective. Legacy `.dump` archives are preserved but are not accepted by this new bundle verifier; restoring an old deployment requires its documented database-only recovery procedure and a compatible old schema/runtime.

保留全部卷的关闭：

```bash
qc stop
```

停止宽限是 90 秒。工人停止领取新任务，并排空进行中的工作。主动停止之后用 `qc up -d` 再次启动；`unless-stopped` 不会撤销操作员的显式停止。升级前先备份，再分阶段构建、应用迁移并核对兼容性。旧镜像不能假定可以读取新迁移后的模式。

```bash
uv sync --frozen --python 3.11 --group dev
.venv/bin/quant-platform --help
.venv/bin/python -m black --check src tests
QUANT_TEST_DATABASE_URL=postgresql://postgres@127.0.0.1:55432/quant_test_platform \

```

PostgreSQL 标记的用例需要指向隔离测试库的 `QUANT_TEST_DATABASE_URL`，库名必须以 `quant_test` 开头。发行包：

```bash
uv build --cache-dir .runtime/uv-cache
QUANT_TEST_ARTIFACTS=1 .venv/bin/python -m pytest tests/test_boundaries_dashboard.py::test_built_distribution_contents
```

进程级冒烟不需要 Docker 守护进程，但需要隔离的 `quant_test*` 管理库，并且会创建一次性 `quant_test_smoke_*` 与 `quant_restore_smoke_*`：

```bash
QUANT_DOCKER_SMOKE=1 \
QUANT_SMOKE_ADMIN_DSN=postgresql://postgres@127.0.0.1:5432/quant_test_smoke \
QUANT_SMOKE_FIXTURES=1 \
  .venv/bin/python tests/docker_smoke.py
```

This smoke script checks migrations, the lightweight dependency boundary, missing-Qlib fail-closed readiness, authenticated API access, browser-independent workers, collector restart, fixture collection/legacy monitoring, and bundle restore to an empty `quant_restore_*` database. It does not validate investment performance or real entitlements. It needs `pg_dump`/`pg_restore` on PATH and no Qlib engine packages in that lightweight environment. For reproducible container and real-Qlib commands, see the [validation report](系统验证报告.md).

For the optional adapter's fixture tests, use a separate environment so the native dependency-isolation tests remain meaningful. These tests inject fixture transport and do not call Eastmoney:

```bash
UV_PROJECT_ENVIRONMENT=.runtime/research-data-venv \
  uv sync --locked --extra research-data --group dev
```
