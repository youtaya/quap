# QUAP 界面层交付文档

## 0. 产物地图与权威边界

界面层由五个产物构成，**每个问题只有一个权威来源**。出现冲突时按本表判定。

| 产物 | 层 | 权威范围 | 不承载 |
|---|---|---|---|
| `docs/prototype/quap-ui-kit.html` | 界面层 | **设计令牌数值**（`:root`）、通用组件（c1–c12）视觉规格、全部状态矩阵、对比度审计实测值 | 交互流程、信息架构、判决面（c13） |
| `docs/prototype/quap-decision-surface.html` | 界面层 | **判决面（c13）**的视觉规格与状态矩阵：判决条、解锁链路、门禁四态、卡点展开块、侧边栏常驻判决块 | 通用组件规格、令牌定义 |
| `docs/UI-DESIGN.md`（本文件） | 界面层 | 令牌命名与准入规则、组件必填状态清单、判定规则、尺寸基线、**c13 的规则性约束**、验收标准、交付顺序 | 具体色值（一律引用 UI Kit） |
| `docs/DESIGN.md` | 交互层 | 信息架构、工作空间划分、状态语言、依赖链模型、文案对照、三层信息密度 | 组件视觉规格、色值 |
| `docs/prototype/quap-interaction-design.html` | 交互层 | 可点击流程原型、命令面板、抽屉、移动端标签栏 | 组件规格、令牌定义 |

**单一事实来源原则。** 令牌只在 `quap-ui-kit.html` 的 `:root` 中定义一次。`DESIGN.md` 的 front matter、`quap-interaction-design.html` 与 `quap-decision-surface.html` 的 `:root` 是**派生副本**，任何令牌变更必须同时同步这三处，并重跑第 7 章的对比度审计。不要在任何新产物里第三次定义令牌。

**c13 为什么不在 UI Kit 里。** 判决面是**组合模式**（由已有通用组件组合而成，且不引入任何新令牌），且只在「今日」一个空间出现。把它塞进通用组件库会误导后续复用——判决条不应出现在「我的组合」或「个股研究」页。因此它的权威是独立原型 + 本文件 2.5 节的**规则性约束**，而不是 UI Kit 的展示台。

## 1. 设计令牌规范

### 1.1 命名规则

令牌名 = `--<族>-<档位>`，族名固定为下表中的十个，不可新增族。

| 族 | 前缀 | 语义 | 数量 |
|---|---|---|---|
| 品牌 | `brand-` | 唯一强调色阶 | 7 |
| 深色面 | `navy-` / `nav-` / `on-brand` | 侧边栏与主行动卡的底色、面上文字、面上白字 | 8 |
| 文字 | `ink-` | 三级文字灰 + 一级非文字色 | 4 |
| 表面 | `canvas` / `surface-` | 四级表面阶梯 | 4 |
| 边框 | `hairline` / `hairline-strong` | 发丝分隔 | 2 |
| 行情 | `quote-` | 涨 / 跌 / 平 | 5 |
| 状态 | `state-` | 六种界面状态，各带底色 | 12 |
| 字体 | `font-` | 字族 | 2 |
| 阴影 | `shadow-` | 五级深度 + 聚焦环 | 6 |
| 动效 | `dur-` / `ease-` | 时长与缓动 | 5 |

档位用数字阶梯 `50 / 100 / 200 / 300 / 400 / 500 / 600 / 700 / 800 / 900 / 950`（数字越小越浅），或语义名（`up` / `down` / `flat` / `ok` / `warn` / `error` / `info` / `busy` / `idle`）。**禁止出现 `--gray-3`、`--color1`、`--light-blue` 这类无语义命名。**

### 1.2 新增颜色的准入门槛

任何新色值进入系统前必须依次通过四道门。四道全过才允许写进 `:root`。

1. **语义门** — 它能否归入第 1.1 节十个族中的某一个？不能，说明需求本身没想清楚，先回到交互层讨论。
2. **对比度门** — 若承载文字，与**所有可能承载它的背景**配对后必须 ≥4.5:1（大字号 ≥3:1）；若不承载文字（分隔线、装饰、禁用态填充），必须在文档中显式标注「非文字」。逐对实测，不得估算。
3. **色相门** — 与已有令牌的色相角差 <15° 视为撞色，必须合并而不是新增。上一轮 `--ink-400`(#5e7088) 与 `--ink-500`(#5b6c86) 就是撞色的典型：**五级文字灰在数学上无法同时满足 4.5:1**，最终收敛为三级文字灰 + 一级非文字色。
4. **稀缺门** — 新增彩色令牌必须回答「它替掉了哪一个」。彩色令牌总数只允许减少或持平，不允许净增。

### 1.3 令牌总表（名称 / 角色 / 约束）

数值见 UI Kit 第 2 章。此表只写**角色与约束**。

| 令牌 | 角色 | 约束 |
|---|---|---|
| `--brand-500` | 主按钮、导航选中、聚焦环、链接 | 全站唯一彩色强调。**从不**作卡片填充或区块背景 |
| `--brand-600` `--brand-700` | 主按钮 hover / active、深色底链接 | 仅状态变化与深色面 |
| `--brand-100` `--brand-50` | 选中标签底、表格选中行、表格行 hover | 只作浅色底，不作文字色 |
| `--brand-200` `--brand-400` | 进度条轨道、图表次要序列 | 非文字 |
| `--navy-900` | 侧边栏、主行动卡填充 | 其上文字必须用 `--nav-*` 或 `#ffffff`，不得用 `--ink-*` |
| `--nav-100` `--nav-200` `--nav-300` | 深色面上的三级文字 | **只允许**出现在 `--navy-*` 底上 |
| `--nav-ok` `--nav-err` | 深色面上的状态标记（侧边栏判决标记） | **只允许**出现在 `--navy-*` 底上；在 `--brand-500` 选中底上须降为 `#ffffff`（红/绿在此底上不足 4.5:1）；必须配字形，不得仅靠颜色 |
| `--ink-900` | 标题、指标数字、正文强调、统计量 | 三级文字灰最深一级 |
| `--ink-700` | 正文、表格单元格 | 三级文字灰中间一级 |
| `--ink-500` | 次级说明、表头、时间戳、占位符 | 三级文字灰最浅一级，仍须 ≥4.5:1 |
| `--ink-200` | 分隔线、装饰图标、禁用态填充 | **非文字**。禁止承载任何文字 |
| `--canvas` `--surface-1/2/3` | 四级表面阶梯 | 层级顺序固定，不得跳级使用 |
| `--quote-up` `--quote-down` `--quote-flat` | 涨 / 跌 / 平 | 只给价格与收益的涨跌量。见第 3 章判定规则 |
| `--quote-up-bg` `--quote-down-bg` | 方向标签底色 | 只配 `--quote-*` 文字 |
| `--state-ok` / `warn` / `error` / `info` / `busy` / `idle` | 六种界面状态 | 只以胶囊徽标或横幅形式出现，各自绑定同名 `-bg` 底色 |
| `--state-ok-line` / `info` / `warn` / `error` | tinted 面板（横幅、判决条、卡点块）的 1px 描边 | 是同名 `-bg` 的**同色相压深**。**不得**用 `--hairline` 给 tinted 面板描边——冷灰线在暖色底上会脏 |
| `--font-num` | 所有数字 | 必须同时启用 `font-variant-numeric: tabular-nums` |
| `--shadow-*` | 五级深度 | 海军蓝着色，不用纯黑。卡片禁用阴影 |
| `--dur-*` `--ease-*` | 动效 | 见第 8 章 |

## 2. 组件规范

### 2.1 组件清单（12 类 / 22 展示台）

展示台编号对应 UI Kit 的 `#c1`–`#c12`。

| # | 组件 | 展示台 | 必填状态 |
|---|---|---|---|
| c1 | 按钮 | 主按钮 / 次按钮 / 文字按钮 / 危险按钮 / 深色面按钮 | 默认、悬停、按下、聚焦、加载中、禁用 |
| c2 | 表单输入 | 文本输入 / 下拉选择 / 多行文本 | 默认、悬停、聚焦、已填写、校验失败、带后缀、禁用 |
| c3 | 选择控件 | 复选框、开关 | 未选中、已选中、禁用 |
| c4 | 徽标与标签 | 状态徽标 / 属性标签 / 选中标签 / 方向标签 | 六状态、中性、三尺寸、选中、方向 |
| c5 | 数据表格 | 标准表格 | 默认、行悬停、行选中、排序态、空态、加载态 |
| c6 | 卡片与指标 | 基础卡片 / 内嵌块 / 指标磁贴 / 主行动卡 | 默认、加载态、空态 |
| c7 | 导航与页签 | 侧边栏导航项 / 页签 / 面包屑 / 分页 | 默认、悬停、选中、禁用 |
| c8 | 反馈提示 | 横幅 / Toast / 气泡 | 成功、信息、注意、错误 |
| c9 | 浮层 | 详情抽屉 / 命令面板 / 确认对话框 | 打开、关闭、加载中 |
| c10 | 引导与进度 | 引导步骤 / 进度条 | 已完成、进行中、未开始、不确定进度 |
| c11 | 图表 | 分时折线 / 五分位柱状图 | 默认、空数据、加载中 |
| c12 | 状态页 | 空状态 / 加载中 / 无权限 | 三种各一 |
| c13 | 判决面 | 判决条 / 解锁链路 / 门禁节点 / 卡点展开块 / 链路图例 | 见 2.5（门禁四态、判决两态、卡点两类） |

> c13 是**判决面专属**组件族，只允许出现在「今日」空间，不进通用组件库。规格见 2.5。

### 2.2 状态矩阵要求

- **交互态必须全部覆盖**：默认 / 悬停 / 按下 / 聚焦 / 禁用。缺任一态视为组件未完成。
- **加载态不得改变尺寸**：加载中只替换内容（文字透明 + 转圈），外框宽高与默认态一致，避免布局跳动。按钮的加载态已验证与默认态同为 104×36。
- **聚焦环只给键盘**：一律使用 `:focus-visible`，不干扰鼠标用户。规格为 3px `rgba(53,103,214,.22)` 外环。
- **禁用态不受对比度约束**（WCAG 1.4.3 豁免），但必须与可用态**一眼可辨**：底色降到 `--surface-3`、文字降到 `--ink-200`。
- **状态不得只由颜色承载**：徽标同时有文字与圆点，错误提示同时有图标与文字，涨跌同时有正负号。

### 2.3 类名与结构约定

- 组件类名用 `.btn`、`.input`、`.card`、`.tbl` 这类**单层名词**；变体用后缀 `.btn-primary`、`.btn-ghost`、`.tag-up`；状态用 `.is-*`（`.is-loading`、`.is-error`、`.is-selected`）或 `:disabled`。
- 尺寸变体用 `.btn-sm` / `.btn-lg`，不用 `.btn-small`。
- 文档专用的强制状态钩子（`.f-hover`、`.f-active`、`.f-focus`）**只允许出现在 UI Kit 文档中**，禁止进入产品代码。
- 可点行必须用 `<button>` 或 `role="row"` + `tabindex`，不得用纯 `<div>` 挂点击。

### 2.4 尺寸基线

| 项 | 值 |
|---|---|
| 按钮高度 | 36px（sm 30 / lg 44） |
| 按钮水平内边距 | 16px（sm 12 / lg 20） |
| 图标按钮 | 36×36 |
| 输入框高度 | 36px（多行最小 76px） |
| 表格表头 / 数据行 | 36px / 40px |
| 侧边栏导航项 | 36px |
| 分页按钮 | 32×32 |
| 指标磁贴最小高度 | 112px |
| 复选框 | 15px（标签整块可点） |

间距基数 **4px**，阶梯 `4 / 8 / 12 / 16 / 20 / 24 / 32 / 48`。圆角阶梯 `xs 4 / sm 6 / md 8 / lg 12 / xl 16 / pill`——**按钮与输入框一律 8px，卡片与表格容器一律 12px，胶囊徽标用 pill**。pill 只留给徽标，不得用于按钮。

### 2.5 状态链与卡点呈现（判决面专属）

判决面是「今日」空间的核心，回答操作员每天唯一的问题：**今天能不能出建议**。它由四个组件构成，只允许出现在判决面。

| 组件 | 类名 | 作用 |
|---|---|---|
| 判决条 | `.verdict` + `.blocked` / `.ready` | 一屏给出判决 |
| 解锁链路 | `.chain` > `.stage` > `.gate` | 把平铺 blocker 还原成依赖链 |
| 卡点展开块 | `.fix` / `.fix.manual` | 卡点就地解决，不跳转 |
| 链路图例 | `.legend` + `.legend-note` | 解释四态语义 |
| **侧边栏常驻判决块** | `.verdict-mini` + `.err` / `.ok` | 判决在任何空间可见 |

#### 侧边栏常驻判决块 `.verdict-mini`

置于侧边栏品牌区之下、一级导航之上。两行：`「今日判决」`（`--nav-100`）+ `「✕ 受阻 · 出不了建议」`（`--nav-err`）/ `「✓ 就绪 · 建议已出」`（`--nav-ok`），左侧 3px 强调条跟随状态色。

**硬约束（三条）：**

1. **不得放进导航项。** 导航项的选中底是 `--brand-500`（#3567d6），红/绿在其上连 3:1 都达不到（实测 `--nav-err` 2.08:1、`--nav-ok` 2.53:1），标记颜色会随选中态失效。判决是**全局状态**，不是导航项的属性。
2. **必须配字形**（✕ / ✓），不得只靠颜色承载状态。文案需同时给出「态 + 后果」（如「受阻 · 出不了建议」），而不是仅一个词。
3. **底必须留在 `--navy-*` 上**，以复用 `--nav-err` / `--nav-ok` / `--nav-100` 在 `--navy-900` 上的实测配对（6.26:1 / 7.59:1 / 8.10:1），不得为它引入新底色。

#### 判决条 `.verdict`

| 态 | 类 | 底 / 边 | 图标 | 主句 |
|---|---|---|---|---|
| 受阻 | `.verdict.blocked` | `state-error-bg` / `#f0c4c8` | ✕（`state-error`） | 「今天出不了建议」 |
| 就绪 | `.verdict.ready` | `state-ok-bg` / `#bfe4d2` | ✓（`state-ok`） | 「今天可以出建议」/「今天的建议已就绪」 |

结构固定四段，顺序不可调换：`.verdict-eyebrow`（「今日判决」，micro 大写）→ `.verdict-sentence`（24px/700）→ `.verdict-reason`（含加粗卡点名词）→ `.verdict-action`（**唯一主行动** + 预计耗时）。

- **判决句必须动作导向，不得复述状态。** 「今天出不了建议」优于「状态：Blocked」。
- **原因必须落在「一个」具名卡点上**，不得罗列多条。
- `.verdict-foot` 承载与主判决**解耦**的次要信息（如五分钟叠加），必须显式写出「不影响日线建议的解锁」，否则会被误读为主判决的一部分。

#### 解锁链路 `.chain`

门禁节点四态，是链路的全部状态语言：

| 态 | 类 | 圆点 | 含义 | 允许出现的内容 |
|---|---|---|---|---|
| 已通过 | `.gate.is-done` | `brand-500` 实心 + ✓ | 该门禁已满足 | 实测值 |
| 卡点 | `.gate.is-blocked` | `state-error` 实心 + ✕ | **可操作**的问题 | 展开块 `.fix` |
| 等待上游 | `.gate.is-waiting` | `surface-3` 空心 | 上游未解除，**状态未知** | 仅「等待上游」 |
| 可以执行 | `.gate.is-pending` | `surface-1` + `brand-400` 描边 | 前置已满足，等触发 | 主按钮 |

**硬约束（四条）：**

1. **「等待上游」不得显示自身失败状态。** 下游门禁不得渲染任何红/黄错误样式或失败原因文案。这是消灭「修完回来还是 Blocked」的关键——下游照实显示失败，操作员会以为问题没解决。
2. **连接轨只在真依赖处绘制。** `.gate-rail` 的语义是「前者未解则后者不动」。并行阶段必须加 `.stage.parallel`，其内部轨道全部隐藏（`.stage.parallel .gate-rail{display:none}`）。**给并行项画轨等于在说谎。**
3. **阶段必须声明依赖性质。** `.stage-kind.par`「3 项互相独立」/ `.stage-kind.seq`「顺序依赖」。不可省略，否则操作员无法判断「修一个够不够」。
4. **阶段一的多个卡点可以同时出现**（其内部互相独立）。阶段二起只呈现**第一个**卡点，其余一律 `.is-waiting`。

#### 卡点展开块 `.fix`

| 变体 | 左边框 | 标识 | 动作区 |
|---|---|---|---|
| `.fix`（可自解） | 3px `state-error` | `.tag-auto` 信息蓝「可自解」 | 主按钮 + 次要按钮 + 预计耗时 |
| `.fix.manual`（需人工） | 3px `state-warn` | `.tag-manual` 注意黄「需人工 · 平台内不可点」 | 指令块 + 「我已处理，重新检测」+ `.fix-hint` |

结构：`.fix-row` × N（`.fix-key` 52px 定宽 + `.fix-val` 自适应），末行为 `.fix-actions`。

- `.fix-key` 取值**限定**为：**未验证 / 已通过 / 为什么**（可自解类）与 **缺失 / 需要 / 命令**（需人工类）。
- 命令必须用 `.cmd`（`white-space:pre-wrap` + `overflow-wrap:break-word`），长命令不得横向溢出。
- **「需运维」类禁止配假按钮。** `.fix-hint` 必须显式写出「不做「修复」按钮——点了也不会发生任何事」，把「为什么没有按钮」讲清楚，否则操作员会反复找。

#### 「我已处理，重新检测」回路

卡点在平台内不可解时，唯一可点的动作是它。规则：

- **不自动轮询。** 自动刷新会让操作员误以为已恢复，且掩盖「服务其实没起来」。
- 点击后按钮进入 `state-busy` 并禁用，重跑判决；结束回到 `blocked` 或 `ready`。
- 该按钮在 `.fix-actions` 中始终是**次按钮**（`btn-secondary`）——它是「告知系统我做了事」，不是「执行修复」。

#### 图例 `.legend`

四态各一项，`.legend-note` 用一句话说明「阶段一独立 / 阶段二起顺序」的差异。**图例文案不得出现「唯一可操作项」这类断言**——它在阶段一不成立。

## 3. 配色语义判定规则

界面上一旦要给某个元素上色，按下面三步判定。**三步的答案互斥，不得叠加。**

```
这个数字 / 状态在表达什么？
│
├─ 价格或收益的涨跌量？
│    → 行情色。裸文字、图表填充、方向标签底色。
│      • 正 → --quote-up（红）  负 → --quote-down（绿）  零或缺失 → --quote-flat
│      • 涨跌量必须带正负号；缺失显示「—」而不是 0.00%
│
├─ 系统的健康度、任务状态、成败？
│    → 状态色。带底色的胶囊徽标或横幅，共六种，不可扩展。
│      • 通过 / 失败用 --state-ok / --state-error
│
└─ 都不是（统计量、质量指标、得分、覆盖率、IC、动量、权重）？
     → 中性色。一律 --ink-900 或 --ink-700，颜色不承载好坏。
       好坏由相邻的状态徽标表达。
```

**三条禁令：**

1. **不给非涨跌量上行情色。** 综合得分、Rank IC、动量、覆盖率、达标率都是统计量，一律中性色。上一轮五分位柱状图的正值柱曾用 `--brand-500`、有效覆盖率曾用 `--quote-up`，均已修正——柱值是收益率，覆盖率是数据质量指标，两者都不是品牌强调也不是涨跌方向。
2. **不用行情色表达成败。** 「首版不达标 10 组」这类通过/不通过的对照表必须用 `--state-ok` / `--state-error`，不用涨跌色。两套色板色相接近但语义严格分离，混用会让状态语言失效。
3. **强调色稀缺。** `--brand-500` 只给主按钮、导航选中、聚焦环、链接。**每视口最多一个主按钮。** 一个界面里出现两个靛蓝填充块，用户就不知道哪个是主操作。

## 8. 动效规范

动效只服务于状态变化的可感知性，不做装饰。全部遵守 `prefers-reduced-motion`。

| 场景 | 属性 | 时长 | 缓动 |
|---|---|---|---|
| 按钮 / 输入框 / 导航项状态变化 | background, border-color, color | 120ms | ease-in-out |
| 开关切换 | background, transform | 180ms | cubic-bezier(.32,.72,0,1) |
| 页签下划线 | color, border-color | 120ms | ease-in-out |
| 抽屉滑入 / 滑出 | transform: translateX | 240ms | cubic-bezier(.32,.72,0,1) |
| 遮罩淡入 | opacity | 180ms | ease |
| 命令面板出现 | opacity, transform: scale(.97→1) | 180ms | ease-out |
| 页面切换 | opacity, translateY(4px→0) | 220ms | ease |
| 进度条推进 | width | 240ms | cubic-bezier(.32,.72,0,1) |
| 骨架屏微光 | background-position | 1400ms 循环 | ease |

**降级规则：** 在 `prefers-reduced-motion: reduce` 下，`animation-duration` 与 `transition-duration` 压到 `.01ms`，`scroll-behavior` 改回 `auto`。骨架屏微光在降级后应替换为**静态 `--surface-3` 色块，而不是消失**——消失会让用户以为加载失败。

**只过渡颜色，不做位移。** 按钮状态变化不得使用 `transform: translateY`，避免密集操作时产生抖动。

## 9. 开发交付

### 9.1 落地顺序（风险从低到高）

| 优先级 | 内容 | 验收标准 |
|---|---|---|
| **P0** | 文案全量中文化 | 7 个工作空间名称与描述、全部按钮 / 标签 / 表头 / 空状态无英文残留。风险极低（纯字符串），收益最大 |
| **P1** | 状态语言统一 | 六状态色板 + 三载体（徽标 / 横幅 / Toast）。顶栏收敛为一行徽标（**且徽标不得表达判决**），不在页面主体重复展示 |
| **P2** | **判决面** | 「今日」重构为判决条 + 解锁链路（2.5）。验收：① 回答「今天能不能出建议」0 次跳转；② `blockers` 平铺数组还原为依赖链，阶段一独立、阶段二起只呈现首个卡点；③ 下游门禁不显示自身失败状态；④ 每个卡点标注动作类型，需运维类无假按钮。**前置：`pipeline.py` 需产出结构化 blocker（带 `gate`/`stage`/`depends_on`/`action_type`），否则依赖关系只能在前端硬编码** |
| **P3** | 信息密度收敛 | L3 明细（原始 JSON、溯源链路、接口明细）全部移出主页面进抽屉；空状态补「下一步」操作 |
| **P4** | 令牌落地 | 把 UI Kit 的 `:root` 令牌注入 Streamlit 自定义 CSS，替换所有硬编码色值 |
| **P5** | 可访问性回归 | 实现后重跑 41 组对比度审计，确认覆写未引入新的不达标配对；七个断点横向溢出为 0 |

> **为什么判决面（P2）排在信息密度收敛（P3）之前：** 信息密度收敛是纯工作量（做抽屉、搬 JSON），而判决面是一次**信息架构决策**——它决定了抽屉该挂在哪个空间。顺序反了，抽屉的归属会全部返工。

### 9.2 Streamlit 组件映射

| 设计组件 | Streamlit 实现 | 落地注意 |
|---|---|---|
| 卡片 / 内嵌块 | `st.container(border=True)` | 需 CSS 覆写边框色与圆角 |
| 指标磁贴 | `st.metric` | 覆写 `[data-testid="stMetric"]`，补口径行 |
| 按钮 | `st.button(type="primary")` | 主按钮每视口仅一个 |
| 表格 | `st.dataframe` | 数值列用 `column_config` 右对齐；涨跌色需 HTML 表格 |
| 状态徽标 | `st.markdown(unsafe_allow_html=True)` | 无原生组件 |
| 横幅 | `st.warning` / `st.error` / `st.info` | 覆写语义色到本规范色板 |
| 详情抽屉 | `st.dialog` | **无原生抽屉**，降级为模态或 `st.expander` |
| 命令面板 | `st.dialog` + `st.text_input` | 快捷键需前端 hack，可降级为顶栏搜索 |
| 引导步骤 | `st.markdown(unsafe_allow_html=True)` | 含状态圆点与进度条 |
| Toast | `st.toast` | 仅用于「操作已提交」类反馈 |
| 骨架屏 | `st.spinner` / 占位 | 无骨架组件 |
| 判决条（c13） | `st.markdown(unsafe_allow_html=True)` | **无原生组件**；态别由 `blockers` 是否为空推导，不得用 `st.error`/`st.success` 替代 |
| 解锁链路（c13） | `st.markdown` 注入 HTML（推荐，一次渲染整条链） | **禁止**用 `st.warning` 逐条平铺——那正是要修掉的做法 |
| 卡点展开块（c13） | `st.container(border=True)` + `st.button` | 「需运维」类指令用 `st.code`（自带复制按钮） |
| 侧边栏常驻判决块（c13） | `st.sidebar` 内 `st.markdown` 注入 HTML | 置于品牌区下、导航上；**不得**放进 `st.radio` 的选项文案里（会随选中态变色失效） |
| 「我已处理，重新检测」 | `st.button` + `st.rerun()` | 点击后 `st.spinner` 期间禁用，避免重复提交 |

### 9.3 已知约束

- **Streamlit 无原生抽屉组件。** 必须保留抽屉效果时需自定义组件，否则降级为模态。
- **Streamlit 无原生骨架屏。** 加载态用 `st.spinner` 或占位块替代，占位块条目数应与真实内容量接近，避免加载完成后布局大幅跳动。
- **涨跌色需 HTML 表格。** `st.dataframe` 无法逐格上色，涨跌列需退化为 `st.markdown` 渲染的 HTML 表格。
