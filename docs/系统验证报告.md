## 3. 复现命令

在仓库根目录，Python 3.11 与可写的隔离 PostgreSQL：

```bash
uv sync --frozen --python 3.11 --group dev
.venv/bin/python -m black --check src tests deploy/prepare_local.py
QUANT_TEST_DATABASE_URL=postgresql://ubuntu@127.0.0.1:5432/quant_test_platform \
  .venv/bin/python -m pytest -ra
.venv/bin/python -m build
QUANT_TEST_ARTIFACTS=1 .venv/bin/python -m pytest tests/test_boundaries_dashboard.py::test_built_distribution_contents
QUANT_DOCKER_SMOKE=1 \
QUANT_SMOKE_ADMIN_DSN=postgresql://ubuntu@127.0.0.1:5432/quant_test_smoke \
QUANT_SMOKE_FIXTURES=1 \
  .venv/bin/python tests/docker_smoke.py
```

集成库名必须以 `quant_test` 开头，否则夹具拒绝执行。冒烟脚本会再创建一次性 `quant_test_smoke_*` 与 `quant_restore_smoke_*`。

本机 HTTP 抽样（测试环境，不会访问 Tushare）：

```bash
export QUANT_DATABASE_URL=postgresql://ubuntu@127.0.0.1:5432/quant_test_platform
export QUANT_API_TOKEN=verification-operator-token-32chars
export QUANT_TUSHARE_TOKEN=not-used-for-live-health
export QUANT_ENVIRONMENT=test
.venv/bin/quant-platform migrate
.venv/bin/quant-platform api --host 127.0.0.1 --port 18080
.venv/bin/quant-platform dashboard --host 127.0.0.1 --port 18501
curl -s http://127.0.0.1:18080/health/live
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:18080/api/v1/status
curl -s -H "Authorization: Bearer $QUANT_API_TOKEN" http://127.0.0.1:18080/api/v1/settings
curl -s http://127.0.0.1:18501/_stcore/health
```

有 Docker 时的镜像冒烟见[部署说明](部署说明.md)。不要把上述测试令牌或测试库 DSN 用于生产。

## 4. 验证中修补的契约缺口

仓库原先在 `pyproject.toml` 的 sdist 清单中声明了 `.dockerignore`，但文件缺失。文档要求密钥不得进入 Docker 构建上下文。本次补上 `.dockerignore`，排除 `.git`、`.venv`、`.runtime`、`deploy/secrets`、`legacy`、`tests` 等，并由 `test_dockerignore_excludes_secrets_and_runtime` 锁住。

## 5. 结论

在隔离 PostgreSQL 与禁止外网的前提下，QUAP 的身份与单位契约、认证 API、看板客户端、持久队列围栏、原生分析快照、人工审批、备份恢复检查和工人独立于浏览器，均与代码及现有部署文档一致。

要进入“行情可用”或“正在实盘监控”，仍须按部署说明配置真实 Tushare 权限、在已验证交易时段观察源时间戳，并保证本平台独占观察列表。要宣布“生产已验收”，还须机外备份恢复和两个完整观察过的交易日。
